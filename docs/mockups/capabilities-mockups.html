Capabilities tab

A sixth tab whose job is one question: what does this Mac let agents do right now, and what has that stopped? Every row is a permission or a self-check from the standing inventory; the counts beside them come from the audit log's host_permission_blocked rows, grouped by permission. A row exists because a switch exists; it badges only while the switch is off and something has hit it.

Three states below: the owner returning to a Mac that blocked things overnight, the same screen with one row opened, and the calm state where nothing needs doing.

The tab is badged with the number of rows that need a decision. Two banners at the top summarise what happened while nobody was here; the groups below are the switches themselves, each with its count and its one button.

What decides the badge.
  • A row counts toward the badge when its switch is off and its request count is above zero, or when a self-check failed. Here: Full Disk Access, Downloads, Messages → 3. Desktop is off but nothing asked, so it does not count.
  • The badge and the counts clear themselves: the status comes from the live inventory, so flipping the switch in System Settings empties the row's "to do" without anyone marking it done. The requests stay listed as history.
  • Dismissing the amber banner hides it until a new block lands. Dismissing a row ("Not now", inside the row) hides it from the badge until a new request hits it, and could tell agents up front through plow_device_status.
  • "Not offered yet" needs one new audit event from the places that already know an ask was unsupported. It doubles as the counted feature-request list.
